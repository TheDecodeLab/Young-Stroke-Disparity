# Step 9: local recovery candidate audit

## Why this step exists

Phase 1 Step 7 found that every record in the derived age 19-50 table
contains MRI, CTA or MRA, which is inconsistent with an intended
denominator that includes patients who received CT alone. The historical
notebook filters for patients with CT, then deletes all CT rows **before**
grouping patients by other imaging. CT-only patients are structurally
lost. The existing manuscript and Step 6 model results should not be
used for population imaging-utilization inference.

The following files were located in the collaborator's *local parent*
directory. They have **not been inspected by the assistant**:

- `../df_merged_age.parquet`: generated by the historical notebook
  before CT rows were removed. The most informative event-level file.
- `../df_trinetx_total_young_wCT.parquet`: may preserve CT records
  in a derived patient table; must verify schema, zero categories, and
  construction logic.
- `../df_trinetx_total.parquet`: possibly a broader cohort.
- `../df_trinetx_total_geo.parquet`: possible earlier cohort with
  geography. DO NOT SHARE GEO DATA.
- `../df_trinetx_total_young.parquet`: the original selected table.

## Run the audit (in the repository root)

```bash
git pull origin analysis-rebuild-phase1-audit
python -m pytest -q
python scripts/step09_audit_recovery.py \
  --files ../df_merged_age.parquet ../df_trinetx_total_young_wCT.parquet \
          ../df_trinetx_total.parquet ../df_trinetx_total_young.parquet \
  --output results/phase1/recovery_candidate_audit.json
```

This command writes only `results/phase1/recovery_candidate_audit.json`,
an aggregate schema/count report, not patient-level records. It lists
column *names* but does not print or export any values of patient_id,
postal_code, geographic fields or dates. The results directory remains
ignored in Git. Inspect the JSON locally before sending it anywhere.

The script scans up to 5 million rows per file by default, in 50,000-row
batches. For larger files it reports only Parquet metadata; do not
increase the limit unless the workstation has enough memory.

## How to read the report

For `df_merged_age.parquet` (procedure events), compare:

- `ct_patients_n` versus `ct_only_patients_n`, computed across all
  diagnosis dates per patient.
- `ct_only_patient_diagnosis_dates_n`, computed with the **patient and
  diagnosis date** as a provisional event key, where dates exist.
- `distinct_patient_diagnosis_dates_n` and the available date columns.

A patient can have CT only at one diagnosis date and advanced imaging
at another. Diagnosis-date pairs are **not proven admissions** because
source encounter identifiers and join cardinality are unverified.

For derived count tables, compare:

- `imaging_columns`: whether CT is explicitly present.
- `rows_with_no_mri_cta_mra` and `ct_only_rows`.
- `duplicate_patient_id_rows`, `min_age`, `max_age`,
  demographic missingness, and invalid procedure counts.

A file named `_wCT` does not establish that it contains valid CT-only
stroke patients. A positive count is only a signal that recovery might
be feasible.

## Scientific decision after audit

**Do not fit new population models yet.** First check that an earlier
file contains all eligible *index ischemic-stroke* patients with CT,
including CT-only cases. Index diagnosis selection must precede MRI,
CTA and MRA filtering. Link each imaging procedure to the correct
index date/encounter and time window. Use a LEFT JOIN to preserve
zero-valued non-CT imaging. Check diagnosis coding, principal status,
first index date, code coverage, duplicate mapping, and cohort attrition.

If `df_merged_age.parquet` can recover the missing CT-only group,
it may avoid a new database export, but source-level validation is
still required. Otherwise, reconstruct from original authorized
diagnosis, encounter, demographic and procedure tables.

## Data governance

The source files may contain pseudonymous patient identifiers and
fine-grained geography. Keep them only in the approved local secure
environment. Do not push Parquet files, notebook previews, patient
rows, record-level reconstructed cohorts, or small-cell tables to the
public GitHub repository. Seek institutional/TriNetX approval for
continued use and resolve any existing public history exposure.
